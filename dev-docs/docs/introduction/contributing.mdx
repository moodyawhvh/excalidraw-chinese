# 贡献指南

欢迎提交 Pull Request。如果是较大的改动,请先[开一个 issue](https://github.com/excalidraw/excalidraw/issues/new),讨论一下你想改什么。

我们有一份[路线图(roadmap)](https://github.com/orgs/excalidraw/projects/3),强烈建议先过一遍,看看有没有你感兴趣的任务。新贡献者建议从 *Easy* 级别的任务入手。

如果你想认领路线图上的某个任务,在对应 issue 下留言即可,项目维护者会把它分配给你,之后你就可以在 issue 里讨论并开工了。

## 环境准备

### 方式一 — 手动配置

1. Fork 并克隆本仓库
1. 运行 `yarn` 安装依赖
1. 用 `git checkout -b your-branch-name` 为你的 PR 创建分支

> 想让 `master` 分支始终对齐上游仓库、并从你 fork 上的分支发起 PR,请执行:
>
> ```bash
> git remote add upstream https://github.com/excalidraw/excalidraw.git
> git fetch upstream
> git branch --set-upstream-to=upstream/master master
> ```

### 方式二 — CodeSandbox

1. 打开 https://codesandbox.io/p/github/excalidraw/excalidraw
1. 关联你的 GitHub 账号
1. 进入左侧的 Git 标签页
1. 点击 `Fork Sandbox`
1. 写你的代码
1. 提交并自动发起 PR

## Pull Request 规范

就算下面哪条没做好、或者不会做,也别慌,我们很乐意帮忙。

### 标题

标题必须以语义化前缀开头:

- **feat**:新功能
- **fix**:修复 bug
- **docs**:仅文档改动
- **style**:不影响代码含义的改动(空格、格式化、补分号等)
- **refactor**:既不修 bug 也不加功能的代码重构
- **perf**:提升性能的代码改动
- **test**:补充缺失的测试或修正现有测试
- **build**:影响构建系统或外部依赖的改动(示例 scope:gulp、broccoli、npm)
- **ci**:改动 CI 配置文件和脚本(示例 scope:Travis、Circle、BrowserStack、SauceLabs)
- **chore**:其他不涉及 src 或测试文件的改动
- **revert**:回滚之前的提交

### 测试

Pull Request 提交后会自动跑测试。请务必查看测试结果并修掉暴露的问题。

同时建议评估一下这次改动是否需要补充测试。对新功能和 bug 修复来说非常推荐这么做。比如,每修一个 bug 就为它写一个测试,可以有效防止代码将来回退。

最后——每个 pull request 都会部署一个随时可用的预演(staging)环境,请务必在上面手动验证你的改动。本地开发环境再怎么贴近生产环境,行为上仍可能存在细微差异。较大的功能建议在多个浏览器里都测一遍。

:::note
部分检查项(例如 `lint` 和 `test`)需要维护者批准后才会运行。
等待批准时,它们会在 PR 检查中显示为 `Expected — Waiting for status to be reported`。
:::

## 翻译

要把 Excalidraw 翻译成其他语言,请访问[我们的 Crowdin 页面](https://crowdin.com/project/excalidraw)。如果想新增一门语言,请先[开一个 issue](https://github.com/excalidraw/excalidraw/issues/new),我们会在平台侧先做好配置。

翻译完成度超过一定阈值(目前为 **85%**)后,就会在应用中上线。
